# API URL and versioning conventions

These rules apply to every OAN Frappe app that exposes a REST API through
`oan_auth_service` (for example `oan_grievance_service`, `oan_a2c`). Follow them for new
apps and new endpoints.

## 1. Public URLs have no `/api` prefix

Clients call:

```
https://<gateway host>/v1/<resource>
```

The gateway rewrites `/v1/...` to `/api/v1/...` before it reaches Frappe.

Why:

- The host already says it is an API (`api.<product>...` or a gateway host), so `/api`
  repeats it. This matches common practice (Google AIP-185, Stripe, GitHub).
- `/api` is Frappe's namespace. Keeping it out of the public URL means the contract does
  not depend on the framework behind it.

Inside Frappe, routes **stay** under `/api/v1/...` (`prefixed("/api/v1/...")`). This is
required, not a style choice:

- `frappe/app.py` sends only paths starting with `/api/` to the REST handler. Any other
  path goes to the website router and returns 404.
- `register_namespace` in `api/middleware.py` refuses prefixes outside `/api/`, so a
  `/v1` route could never be JWT-protected.

So do **not** register `/v1/...` aliases inside an app. They are never reached. Put the
alias in the gateway, once, for every app.

## 2. Where each piece lives

| Piece                                        | Path form                          | Generated by                                     |
| -------------------------------------------- | ---------------------------------- | ------------------------------------------------ |
| Frappe routes                                | `/api/v1/...`                      | `prefixed(...)` in `api/v1/*.py`                 |
| Internal spec `openapi/openapi_v1.yaml`      | `/api/v1/...`, bench server        | `openapi/generate_openapi_spec.py`               |
| Public spec `openapi/openapi_v1.public.yaml` | `/v1/...`, gateway servers         | same script, via `gateway_apisix.publicize_spec` |
| Gateway `apisix/adc.yaml`                    | matches `/v1/...` only             | `apisix/generate_apisix_config_from_spec.py`     |
| Postman collections                          | `/api/v1/...` against a bench site | from the internal spec                           |

The public spec is the client contract. Share it with frontend and partner teams, not
the internal one. The path rewrite and helpers live in
`oan_auth_service/gateway_apisix.py` (`public_path`, `publicize_spec`, `proxy-rewrite`).

The gateway serves `/v1/...` only. `/api/v1/...` through the gateway returns 404: there
is one public spelling, and `/api/v1` is reachable only on the bench itself (local
development, Postman against a site).

## 3. Versioning

- Major version only, as the first path segment: `/v1`, `/v2`.
- Additive changes stay in the same version: new endpoints, new optional request
  fields, new response fields.
- Breaking changes need a new version: removing or renaming a field or endpoint, changing
  a type, making an optional field required, narrowing accepted values.
- Run old and new versions side by side until the old one is retired.

## 4. Deprecation and retirement

Add these headers only to endpoints that are being retired, from the day the
deprecation is announced. Do not add them to healthy endpoints.

```
Deprecation: @1767225600                 # RFC 9745, when it was deprecated
Sunset: Wed, 30 Jun 2027 00:00:00 GMT    # RFC 8594, when it stops working
Link: </v1/auth/password/forgot>; rel="successor-version"
```

Policy: at least 6 months between `Deprecation` and `Sunset`, announced in the
changelog. Mark the operation `deprecated: true` in the spec as well.

## 5. Shared capabilities have one path

Auth is served by `oan_auth_service` at `/v1/auth/*`, `/v1/admin/*` and
`/v1/notifications/*` for every product. Apps do not re-publish these paths under their
own prefix or re-register them.

## 6. Resource naming

Plural nouns, lowercase kebab-case segments, lifecycle actions as `POST` sub-paths:
`/v1/grievances/{ticket_number}/attachments`, `/v1/grievances/{ticket_number}/action`.

## 7. Checklist for a new app or endpoint

1. Declare the route with `prefixed("/api/v1/<resource>")`.
2. Regenerate the specs: `python3 openapi/generate_openapi_spec.py`.
3. Give the operation a throttling tier: in an app, the `tier=` on its `@route` (or the
   app's `TIER_OVERRIDES`); in oan_auth_service, `AUTH_TIER_OVERRIDES` in
   `gateway_apisix.py`, keyed by the public `/v1/...` path. Then regenerate the app's
   `apisix/` output. oan_auth_service has no gateway config of its own: each app includes
   its endpoints.
4. Document the public `/v1/...` URL in READMEs and client docs, never `/api/v1/...`.
